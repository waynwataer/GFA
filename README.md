# GFA Haverhill Dashboard · 자비스(Jarvis) v6.1

## 이번 업그레이드에서 고친 것

### 1. 주(State) 클릭 후 주거인구가 안 바뀌던 문제 [원인 확정]
클릭 시 `setTimeout(550ms)`으로 인구를 다시 불러왔는데, 먼 주로 이동하는
`map.panTo()` 애니메이션이 그 안에 끝나지 않으면 **아직 이동 전(예: Haverhill)
좌표로 조회**해버려, 어떤 주를 클릭해도 항상 이전 지역 데이터만 다시 뜨는
버그였습니다. 고정 시간 대기 대신, 지도가 실제로 멈추는 `idle` 이벤트를
1회성으로 기다렸다가 그 시점의 정확한 좌표로 조회하도록 고쳤습니다.
(재현 시뮬레이션으로 기존 코드는 항상 42.7762,-71.0773을 조회하고, 수정 후에는
클릭한 주의 실제 좌표를 조회하는 것을 확인했습니다.)

### 2. "구글시트 기록 확인 실패 · 백엔드 주소 확인 필요" 메시지 개선
- **백엔드(`chat-log.js`) 견고화**: CORS 헤더 설정과 전체 로직을 try/catch로
  감싸, 예상치 못한 오류가 나더라도 CORS 헤더가 없는 상태로 응답이 나가는
  일이 없도록 했습니다. (CORS 헤더가 빠지면 브라우저가 응답을 통째로 숨기고
  `fetch()`가 "Failed to fetch"라는, 원인을 알 수 없는 네트워크 오류로 실패한
  것처럼 보이게 됩니다 — 이게 가장 유력한 원인이었습니다.)
- **진단 메시지 구체화**: 이제 실패 시 브라우저가 준 실제 오류 메시지를 함께
  보여주고, 상태 텍스트를 클릭하면 `/api/chat-log` 주소를 새 탭에서 바로 열어
  직접 확인할 수 있습니다. 정상이면 `{"ok":true,"configured":false}` 같은
  JSON이, 배포가 안 됐다면 Vercel의 404 페이지가 보일 것입니다.
- 그래도 계속 실패한다면, Vercel 프로젝트의 **Functions** 탭에 `chat-log.js`가
  실제로 배포 목록에 있는지 꼭 확인해 주세요 — `ai-compare.js`/`population.js`는
  있는데 `chat-log.js`만 빠진 상태로 업로드된 경우가 가장 흔한 원인입니다.

### 3. "GPT 버전" 표시 제거
자비스 답변 카드 옆에 뜨던 `gpt-5.6` 같은 모델명 배지를 없앴습니다. 이제
"🤖 자비스"만 표시됩니다.
